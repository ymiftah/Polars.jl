Functions ​

Top-level functions that construct an Expr from scratch — column references, literals, conditionals, and row-wise reductions across several expressions at once.

Column references ​

Polars.col Function
julia
col(name::Union{String,Symbol})::Polars.Expr

Returns an expression referencing a column in a dataframe. The special column name "*" will select all columns in the dataframe.

source
Polars.nth Function
julia
nth(n::Int64)::Polars.Expr

Returns an expression referencing the nth column in a dataframe. The n argument is one indexing based, meaning that columns start at 1. Negative numbers reference columns starting from the end.

source
Polars.element Function
julia
element()::Polars.Expr

A placeholder for "the values in this group", used to build the agg expression passed to pivot – e.g. Base.sum(element()), Base.first(element()) (the default).

source

col(name) references a column by name (or "*" for all); nth(n) references the nth column (1-indexed; negative counts from the end). element() is a placeholder for "the values in this group", used to build pivot's agg argument (see DataFrame).

To reference columns by dtype, position, or name pattern instead of one at a time, see Selectors.

Literals & casting ​

Polars.lit Function
julia
lit(x)::Polars.Expr

Transforms a literal value as an expression which will broadcast when used with other expressions.

source
Polars.when Function
julia
when(cond::Polars.Expr, then, otherwise)::Polars.Expr

Ternary conditional expression: evaluates to then for rows where cond is true, and to otherwise otherwise. then/otherwise may be Polars.Exprs or literal scalars (promoted via lit).

source
julia
when(pairs::Pair...; otherwise)::Polars.Expr

Chained conditional expression. Evaluates each cond => value pair in order and takes the first value whose cond is true, falling back to otherwise if none match. conds must be Polars.Exprs; values and otherwise may be Polars.Exprs or literal scalars (promoted via lit).

julia
when(col("x") == 1 => "one", col("x") == 2 => "two"; otherwise = "other")
source

lit(x) turns a scalar value into an expression (broadcasts in operations); it also accepts a Dates.Date/Dates.Time/Dates.DateTime directly:

julia
using Dates
dfdate = DataFrame((; d = [Date(2024, 3, 15), Date(2024, 3, 16), Date(2024, 3, 17)]))
filter(dfdate, col("d") == lit(Date(2024, 3, 15)))
1×1 DataFrame
 d          
 Dates.Date 
────────────
 2024-03-15

Two caveats

  • Polars.Meta.is_literal(lit(Date(...))) is false — see Meta and Limitations.

  • A DateTime literal is built at nanosecond resolution, so it inherits the same ~1678–2262 range limit as any other nanosecond-precision DateTime column in this package — see Limitations.

when(cond, then, otherwise) — ternary: evaluates to then where cond is true, otherwise elsewhere. Both branches can be Exprs or scalar values (promoted via lit). A chained when(pairs...; otherwise) form is also available for multi-branch conditionals.

julia
df = DataFrame((; x = [1, 2, 3, 4], y = [true, false, true, false]))
select(df, when(col("y"), lit("yes"), lit("no")))
4×1 DataFrame
 literal 
 String  
─────────
     yes
      no
     yes
      no

For cast/cast_datetime/cast_duration/cast_decimal/cast_categorical, see Casting on the Expressions page.

Horizontal (row-wise) reductions ​

Polars.all_horizontal Function
julia
all_horizontal(exprs...)::Polars.Expr

Row-wise (horizontal) boolean AND across exprs. The output column is named "all" unless aliased.

source
Polars.any_horizontal Function
julia
any_horizontal(exprs...)::Polars.Expr

Row-wise (horizontal) boolean OR across exprs. The output column is named "any" unless aliased.

source
Polars.min_horizontal Function
julia
min_horizontal(exprs...)::Polars.Expr

Row-wise (horizontal) minimum across exprs. The output column is named "min" unless aliased.

source
Polars.max_horizontal Function
julia
max_horizontal(exprs...)::Polars.Expr

Row-wise (horizontal) maximum across exprs. The output column is named "max" unless aliased.

source
Polars.sum_horizontal Function
julia
sum_horizontal(exprs...; ignore_nulls::Bool=true)::Polars.Expr

Row-wise (horizontal) sum across exprs. If ignore_nulls is true (default), nulls are treated as 0; if false, any null in a row makes that row's sum null.

source
Polars.mean_horizontal Function
julia
mean_horizontal(exprs...; ignore_nulls::Bool=true)::Polars.Expr

Row-wise (horizontal) mean across exprs. If ignore_nulls is true (default), nulls are excluded from the average; if false, any null in a row makes that row's mean null.

source

Each takes a list of expressions and reduces across them, per row — the row-wise counterpart to the (per-column, per-group) aggregation functions on the Expressions page. Each defaults to an output name matching its own function name ("all", "min", "sum", ...) unless aliased. sum_horizontal/mean_horizontal take an ignore_nulls keyword (default true: treat nulls as 0/exclude them from the average; false: any null in a row makes that row's result null).

julia
df10 = DataFrame((; a = [1, 2, missing], b = [4, missing, 6], c = [7, 8, 9]))
select(
    df10,
    min_horizontal(col("a"), col("b"), col("c")) |> alias("row_min"),
    sum_horizontal(col("a"), col("b"), col("c")) |> alias("row_sum"),
)
3×2 DataFrame
 row_min  row_sum 
 Int64    Int64   
──────────────────
       1       12
       2       10
       6       15

String & array combination ​

Polars.format Function
julia
format(fmt::AbstractString, args...)::Polars.Expr

Formats args into fmt, where each {} placeholder consumes one argument in order. Each argument is an Expr, or a String/Symbol naming a column (as in col) – a bare numeric literal is not accepted here, unlike some other functions in this package; wrap it in lit first. The number of {} placeholders must equal the number of args, or a PolarsError is raised. fmt also accepts upstream's {0}/{name} forms (positional/named placeholders, matching args by index or resolving name directly as a column reference) – but not mixed with bare {} in the same call. The row-wise counterpart of Base.string over several columns; see also concat_str, which joins with a fixed separator instead of a template.

source
Polars.concat_arr Function
julia
concat_arr(exprs...)::Polars.Expr

Horizontally concatenates exprs into a single fixed-size Array column, one element per input expression – the Array-dtype counterpart of concat_list. All inputs must share a dtype. Building the plan and collecting it both succeed, but nothing that needs to resolve the Array dtype does: collect_schema, schema, and indexing into a collected DataFrame's Array column all raise an ErrorException from the Arrow schema parser, which does not yet recognize the fixed-size-list format – this is a package limitation, not a query error. Use explain to confirm the plan was built, or cast the result away from Array before inspecting it.

source
Polars.concat_str Function
julia
concat_str(exprs...; separator::AbstractString="", ignore_nulls::Bool=false)::Polars.Expr

Row-wise (horizontal) string concatenation across exprs (columns or expressions – non-string dtypes are cast to string first), joined by separator. If ignore_nulls is false (default), any null in a row makes that row's whole result null; if true, nulls are skipped (treated as empty) instead. Distinct from Strings.join (an aggregation across all rows into one value) and Lists.join (joins each row's own list independently) – this concatenates sibling columns within each row.

source
Polars.concat_list Function
julia
concat_list(exprs...)::Polars.Expr

Horizontally concatenates the List-typed exprs into a single List per row (row i's output is every input's row-i list, in order, flattened one level). Distinct from Lists.join (string-joins one row's own list into a scalar) and concat (stacks whole frames, not per-row lists). Errors if exprs is empty.

source

format(fmt, args...) fills a {}-templated string with args, one per placeholder, row-wise — the row-wise counterpart of Base.string over several columns. concat_arr(exprs...) combines exprs row-wise into a fixed-size Array column; see its docstring for the current limitation on materializing/introspecting an Array-dtype result. concat_str/concat_list are the same family of row-wise horizontal combinators, joining into a String/List respectively instead of a fixed-size Array.

julia
df11 = DataFrame((; name = ["a", "b"], age = [1, 2]))
select(df11, format("{} is {}", col("name"), col("age")) |> alias("greeting"))
2×1 DataFrame
 greeting 
 String   
──────────
   a is 1
   b is 2

Temporal constructors ​

Polars.datetime Function
julia
datetime(year, month, day; hour=0, minute=0, second=0, microsecond=0,
         time_unit::Symbol=:us, time_zone::Union{Nothing,AbstractString}=nothing,
         ambiguous::AbstractString="raise")::Polars.Expr

Constructs a DateTime column from component expressions (or plain scalars). Distinct from cast_datetime, which reinterprets/casts an existing value rather than building one from parts. ambiguous controls how a local time that occurs twice (a DST fall-back) resolves – same values as Dt.replace_time_zone's ambiguous.

The output column is always named "datetime" for any non-all-literal input (an upstream Rust Expr::Alias(..., "datetime") this package's binding calls unmodified, see CLAUDE.md) – not the first argument's own name (e.g. "year"), which a newer upstream py-polars test (test_datetime_name) expects. That naming ("follow left-hand rule") is marked // TODO: ... in Polars 2.0 in the exact polars-plan version this package is pinned to (0.54.4) and is not yet implemented there; confirmed live, not fixable from this package without bumping the vendored crate version (out of scope here, see plans/parity/tier12-sweep-temporal.md).

source
Polars.duration Function
julia
duration(; weeks=0, days=0, hours=0, minutes=0, seconds=0, milliseconds=0, microseconds=0,
          nanoseconds=0, time_unit::Symbol=:us)::Polars.Expr

Constructs a Duration column from component expressions (or plain scalars), each may be negative. Distinct from cast_duration, which reinterprets/casts an existing value.

source
Polars.date Function
julia
date(year, month, day)::Polars.Expr

Constructs a Date column from component expressions (or plain scalars). Composes datetime + Dt.date (this package has no separate Rust-side Date constructor – neither does upstream py-polars, whose own pl.date does the same composition in Python), and matches upstream's own explicit .alias("date") on the result – datetime's own output name (currently always "datetime", see its docstring) would otherwise leak through unchanged, since Dt.date (a plain namespaced extraction) does not rename its input.

source
Base.Libc.time Method
julia
Base.time(hour, minute=0, second=0, microsecond=0)::Polars.Expr

Constructs a Dates.Time column from component expressions (or plain scalars). Extends Base.time (which takes no arguments and returns wall-clock seconds) rather than shadowing it – same precedent as this package's Base.get/Base.sort/Base.tail extensions in src/expr/expr.jl.

Arguments are constrained to Expr/Real rather than left untyped: time is both a Base function and exported from here, so an Any-typed extension would capture every two-to-four argument time(...) call in any downstream session, turning what should be a MethodError into a confusing failure inside expression construction. Aliased to "time" on the result, matching upstream's own explicit .alias("time") – see date's docstring for why this is needed rather than relying on datetime's output name.

source
Polars.from_epoch Function
julia
from_epoch(expr::Polars.Expr, time_unit::Symbol=:s)::Polars.Expr

Interprets expr (a numeric column) as a count of time_units since the Unix epoch and constructs the corresponding Date/DateTime column – the inverse of Dt.epoch. Mirrors upstream pl.from_epoch's own scaling exactly (py-polars/src/polars/functions/lazy.py): :ns/ :us are a direct physical cast to Datetime at that same resolution; :s/:ms are scaled up to microseconds first (:s x1_000_000, :ms x1_000) and always land on Datetime(:us) – not a direct physical cast to Datetime(:ms), which would silently truncate a fractional- second/sub-millisecond input; :d casts to Date, whose physical representation is already days-since-epoch.

source

datetime/date/Base.time build a Datetime/Date/Dates.Time column from component expressions (year/month/day, hour/minute/second/microsecond); duration builds a Duration column from a set of unit-named components. from_epoch is the inverse of Dt.epoch: it interprets an integer column as a count of time_units since the Unix epoch.

julia
dft = DataFrame((; y = [2024, 2025], m = [1, 6], d = [15, 30]))
select(dft, datetime(col("y"), col("m"), col("d"); hour = 12) |> alias("dt"))
2×1 DataFrame
 dt                  
 Dates.DateTime      
─────────────────────
 2024-01-15T12:00:00
 2025-06-30T12:00:00
