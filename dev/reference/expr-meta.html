Meta ​

The Polars.Meta namespace (py-polars' Expr.meta) inspects an expression tree itself – what column(s) it reads from, what name it would produce, whether it's a plain column or a literal – without needing a DataFrame/LazyFrame to run it against.

Polars.Meta Module
julia
Meta

Introspection over Polars.Expr values. Every function here accepts anything _as_expr accepts (an Expr, a Polars.Selector, or a column-name String/Symbol) and inspects the expression tree itself – not any DataFrame/LazyFrame it might later be applied to, so no schema is consulted (e.g. tree_format/show_graph render unresolved column types as untyped).

source
Polars.Meta.output_name Function
julia
output_name(expr)::String

Returns the single output column name expr would produce, e.g. col("x") -> "x", col("x") |> alias("y") -> "y", col("x") + col("y") -> "x" (the left/first root column). Raises a PolarsError if expr has no single well-defined output name – e.g. a wildcard or a selector-expanded expression that can match more than one column.

source
Polars.Meta.is_column Function
julia
is_column(expr)::Bool

Returns true if expr is a plain (non-regex) column reference, e.g. col("x"). Returns false for anything else, including an aliased column (col("x") |> alias("y")) or a Selectors expression.

source
Polars.Meta.is_literal Function
julia
is_literal(expr; allow_aliasing::Bool=false)::Bool

Returns true if expr is a literal value, e.g. lit(1). If allow_aliasing, an aliased literal (lit(1) |> alias("x")) also counts as one; otherwise it does not.

source
Polars.Meta.has_multiple_outputs Function
julia
has_multiple_outputs(expr)::Bool

Returns true if expr can expand to more than one output column – e.g. a Selectors expression like Selectors.numeric(). Returns false for a plain single-column expression like col("x").

source
Polars.Meta.undo_aliases Function
julia
undo_aliases(expr)::Polars.Expr

Strips any renaming (alias/keep_name) applied anywhere in expr, returning the same expression with those renames removed.

source
Polars.Meta.root_names Function
julia
root_names(expr)::Vector{String}

Returns the names of the root (leaf) columns expr reads from, e.g. col("x") + col("y") -> ["x", "y"]. Empty for an expression with no column reference at all, e.g. a bare literal lit(1).

source
Polars.Meta.tree_format Function
julia
tree_format(expr)::String

Renders expr as a human-readable tree. No frame schema is consulted, so unresolved column types show as untyped. See also show_graph for a Graphviz rendering of the same tree.

source
Polars.Meta.show_graph Function
julia
show_graph(expr)::String

Renders expr as a Graphviz (.dot) graph description – write the result to a .dot file (or pass it to a Graphviz renderer) to visualize. See also tree_format for a plain-text rendering of the same tree.

source
julia
Polars.Meta.output_name(col("x") + col("y")), Polars.Meta.root_names(col("x") + col("y"))
("x", ["x", "y"])

output_name/root_names follow the whole expression tree, not just its top node – an alias buried inside one operand of a binary operation doesn't change the overall output name:

julia
chained = (col("x") + col("y")) |> alias("total")
Polars.Meta.output_name(chained), Polars.Meta.output_name(Polars.Meta.undo_aliases(chained))
("total", "x")

output_name/root_names need at least one well-defined root column: a wildcard or a Selectors expression that could match more than one column raises a PolarsError from output_name (there is no single name to report), while root_names on a column-free expression (a bare literal) returns an empty Vector{String} rather than erroring:

julia
try
    Polars.Meta.output_name(col("*"))
catch e
    println(sprint(showerror, e))
end
PolarsError: unable to find root column name for expr 'cs.all()' when calling 'output_name'
julia
Polars.Meta.root_names(lit(1))
String[]

tree_format/show_graph render the same underlying tree as plain text or as a Graphviz graph description, respectively – no DataFrame/LazyFrame schema is consulted, so unresolved column types show as untyped:

julia
print(Polars.Meta.tree_format(col("x") + col("y")))
            0            1
   ┌───────────────────────────
   │
   │  ╭───────────╮
 0 │  │ binary: + │
   │  ╰─────┬┬────╯
   │        ││
   │        │╰───────────╮
   │        │            │
   │    ╭───┴────╮   ╭───┴────╮
 1 │    │ col(y) │   │ col(x) │
   │    ╰────────╯   ╰────────╯

show_graph returns Graphviz .dot source rather than a picture – rendering it (e.g. by piping to dot -Tsvg, or via a Julia binding to Graphviz such as GraphViz.jl) turns it into an actual diagram:

julia
using GraphViz
q = when(col("qty") .> 1, col("price") * col("qty"), lit(0.0)) |> alias("revenue")
g = GraphViz.Graph(Polars.Meta.show_graph(q))
GraphViz.layout!(g; engine = "dot") # "dot" lays out top-down, matching a tree; the package default ("neato") is spring-directed
g
